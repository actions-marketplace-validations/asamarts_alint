# v0.12 post-build coverage re-analysis (111 repos)

Status: **Analysis — 2026-06-03.** The successor to
[`case_study_log.md`](./case_study_log.md): re-scores the 111-repo study against
the v0.12 **build** delta (file_graph, the unified cross_file kind, the
git-extract family, selector polish, the C-tuning fixes), maps the locked backlog
to what shipped, and proposes the architecturally-clean way to close the residual.
Grounded in a fresh pass over all 110 [`corpus/`](./corpus/) configs + the
[architecture synthesis](./architecture_synthesis.md) 5-axis model.

> **Method caveat (load-bearing).** The 110 corpus configs were authored *before*
> the v0.12 build, so they express gaps against the *old* kind set and therefore
> **systematically understate** post-v0.12 coverage. Several recorded "B gaps" are
> in fact already closed by shipped kinds — istio's `dependabot` list-vs-list and
> mypy/numpy requirement-set parity (`cross_file set_equals`), ClickHouse per-file
> line-length (`line_max_width`), and every whole-repo import-firewall /
> codegen-freshness / orphan check (`file_graph`, which *no* config uses yet). The
> figures below correct for this; a re-authoring pass would make the uplift visible
> in the configs themselves.

## 1. Headline: 61% → ~85% of the *addressable* surface

The study measured `coverage_today = A/(A+B+C) = 457/748 = 61%` against the
pre-build kinds (B=144 gaps, C=147 sharp-edges; ~1731 D behaviours correctly
excluded as execution non-goals). v0.12 converts the **bulk of B→A and roughly
half of C→A**, lifting native coverage to an estimated **~640/748 ≈ 85%** of
addressable. The residual clusters tightly (§3): in the per-repo pass (§7),
**42 of 110 repos now carry no residual at all** for their addressable surface,
and ~45 of the ~68 that do fall into just two buckets (mutating codegen-freshness
and a set of small sharp-edges).

The decisive result: **5 of 6 Tier-1 backlog items shipped**; the one that did
not — mutating codegen-freshness — is the single dominant remaining gap.

## 4. Major themes

1. **"Compose, don't accrete" was vindicated.** ~50 study candidates collapsed to
   2 new primitives (`file_graph`, `cross_file`) + shared-axis extensions. The
   residual is *also* mostly axis-extensions, not kinds.
2. **The corpus understates real coverage** because it predates the build —
   `file_graph` is unused in every config yet would convert many recorded B/D
   items to native A. A re-authoring pass would lift the visible number.
3. **alint's value is cross-file coherence + headers + firewalls + structure +
   codegen-freshness — never execution.** Every repo's *bulk* enforcement is D
   (build/test/AST/lint/format), which alint orchestrates via `command` but
   correctly does not reimplement. The most-reached-for capability across all
   archetypes is **cross-file value/version coherence**.
4. **The one big remaining capability is mutating codegen-freshness** — recurs
   ~10–12× and is the only Tier-1 item left.
5. **A long tail of cheap extract/normalize polish has outsized unblocking value**
   — `occurrence:`, JSONC, `basename`/`casefold`, multi-capture. Each is small;
   together they unblock ~10 repos' otherwise-A rules.
6. **Archetype predicts coverage** (§5).
7. **A handful of scoping sharp-edges** (root-file no-op, tracked-but-gitignored)
   silently disable correct rules — small fixes, high trust impact.

## 5. Per-repo replaceability — three archetypes, and why alint fits

Coverage is predicted almost entirely by archetype:

**A. Focused libraries + coherence-heavy repos → 70–100% replaceable.**
*pydantic, serde, clap, curl, flask, prometheus, scikit-learn, phoenix, prettier,
ruff, axum, pandas.* alint replaces their bespoke version-sync, hygiene, and
header scripts almost entirely. **Why alint:** one `.alint.yml` replaces a pile of
`scripts/check-*.{sh,py,pl}` (curl's `spacecheck.pl` battery → 10 native rules;
ruff's `cargo dev generate-all` git-diff; pydantic's 4-way version sync) — exactly
the cross-file/hygiene/header checks teams hand-roll and under-test.

**B. Big polyglot monorepos with grep-suites → 40–70%.** *kubernetes, ClickHouse,
rust, spring-boot, symfony, airflow, deno, elasticsearch.* alint natively replaces
the grep-rule + structure + header + firewall portion (k8s
`verify-boilerplate.sh` / `verify-prometheus-imports.sh`; ClickHouse
`various_checks.sh`; spring `checkstyle` header+import+sort); the AST/codegen
portion stays D or hits the residual. **Why alint:** consolidates dozens of
`hack/verify-*.sh` / checkstyle regex modules into one reviewable file with a real
schema, and `file_graph` now expresses the whole-repo layering firewalls these
repos hand-roll.

**C. Pure-execution repos → 0–30% addressable (but a high % of a *small*
surface).** *gin, express, axios, swift, alamofire, rich, vapor, gohugo,
tensorflow, valkey.* Enforcement is ~100% tool execution (golangci-lint, eslint,
xcodebuild, pytest). **Not an alint shortfall** — D is correctly out of scope.
alint's role here is *value-add* coherence/structure (manifest pins,
governance-file presence), not gating. Honest positioning: alint complements their
CI; it doesn't replace it.

## 6. How to extend alint cleanly — keep enriching the 5 shared axes

The architecturally-clean move is to **resist new kinds** and keep pushing
capability into the five shared, composable axes, so the DSL stays one learnable
vocabulary (`extract:` / `normalize:` / `select:` / `relation:` / `require:`).

**① Source / Extract (highest ROI, cheap, all in `crate::extract` so every kind
gains them):**
```yaml
extract: { regex: 'version: (.*)', occurrence: first }              # latest changelog entry
extract: { json: "$.references", format: jsonc }                    # tolerate tsconfig comments / trailing commas
extract: { compose: "{maj}.{min}", from: [{regex: 'MAJOR (\d+)'}, {regex: 'MINOR (\d+)'}] }  # version compose
```
`occurrence:` and `jsonc` are one-field additions; `compose:` is the single
structural extract addition (joins sub-extracts) and retires the rails/protobuf
gap.

**② Normalize (promote the deferred transforms into the shared list — free
everywhere now that it is composable):**
```yaml
normalize: [casefold]                  # unique_by case-insensitive dup → closes tensorflow + git
normalize: [strip_prefix: "pnpm@"]     # angular packageManager; turbo @scoped dir-vs-name
normalize: [basename]
```

**③ Relation — essentially complete.** Don't add. The "derived-file =
transform(source)" case (sqlalchemy) is codegen-freshness (below), not a relation.

**④ Quantifier — add ONE primitive: `for_each_match` (in-file block/line
for-all).** The clean home for the entire line/block-grammar cluster, mirroring
`for_each_dir`'s shape but over in-file regions:
```yaml
- kind: for_each_match
  paths: "CHANGELOG.md"
  select: '^\* '                 # each matching line / block is an element
  require:                       # nested predicates, same vocabulary
    - { kind: file_content_matches, matches: '\(\[#\d+\]\(.+\)\)\.$' }
```
One kind absorbs rubocop's 15-clause changelog grammar, count-header,
`max_consecutive_spaces`, and intra-file reference checks — instead of 4+ narrow
kinds.

**⑤ Graph — complete.** Optionally extend `file_graph` nodes to intra-file
granularity later for `implicit_link_resolves`; low priority.

**Two genuinely-new, parameterized (not narrow) builds for the true residual:**
- **Mutating `generated_file_fresh` mode** (#1 residual). A `mode: regen` /
  `writes_in_place: true` flag on the existing kind: run the declared generator,
  then assert the working tree is clean over a path scope. Lives on the existing
  spawn trust-tier next to the stdout-diff form — a *mode*, not a new kind. Closes
  ~10–12 repos.
- **Glob-union source for `cross_file`** (#6 / B2). Let `source` / `targets` take
  `files: <glob>` producing the *union* of extracted values, then `set_equals`.
  Reuses the shipped set relations; closes symbol-set parity + cross-language API
  completeness. (This is the *useful* slice of the dropped `file_set` — a union
  *source*, not a path-set kind.)
- **`registry_paths_resolve` lines/regex source** (#5 / B1) — one extract-source
  addition; the reverse is handled by `file_graph no_orphans`.

**The extensibility boundary — keep it where it is.** For the genuine long-tail
(AST, NLP, tool-specific digests like cpython's Argument Clinic, sanitizers), the
architecturally-correct answer is *not* native expression — it is the existing
`command` / `command_idempotent` spawn tier as the sanctioned, trust-gated escape
hatch. Native investment stays on the data-shape axes, which is exactly where the
corpus shows the replaceable surface lives. This keeps the DSL readable (every
native kind draws from one vocabulary) while extensibility is unbounded via the
command tier.

**Suggested build order** (by hard residual count): mutating-gff (#1, **≈23
repos** — the dominant gap) → the sharp-edge cluster (#7, **≈22 repos** — cheap,
high unblocking value: `file_header` options, root-file scoping, `unique_by` key
normalize) → extract refinements `occurrence` / `jsonc` / `basename` + `casefold`
(#4 + #8, **≈17 repos**) → `for_each_match` (block grammar, #2) → glob-union
source + `registry_paths_resolve` text source (#6 / #5 / B1-B2).
